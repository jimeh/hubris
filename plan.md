# Plan: Switch Frontend from Node.js/pnpm to Bun

## Goal

Replace Node.js + pnpm with Bun as the frontend's JS runtime and package
manager. No functional changes to the app — same deps, same build output.

## Scope

7 files to modify, 1 file to delete, 1 file generated by `bun install`.

## Steps

### 1. Remove pnpm lockfile

Delete `frontend/pnpm-lock.yaml`. Bun will generate `bun.lock` in its place.

### 2. Update `frontend/package.json`

Replace the pnpm-specific `onlyBuiltDependencies` config with Bun's
`trustedDependencies`. Bun defaults to blocking lifecycle scripts for all
packages; `trustedDependencies` is the allow-list.

The packages that need lifecycle scripts: `esbuild` (postinstall downloads
platform binary). `rollup` and `lightningcss` use optional deps with
`os`/`cpu` fields instead of postinstall, so they don't need to be trusted.

```json
{
  "pnpm": {
    "onlyBuiltDependencies": ["esbuild"]
  }
}
```

becomes:

```json
{
  "trustedDependencies": ["esbuild"]
}
```

Note: `trustedDependencies` is a top-level field in package.json for Bun
(not nested under a `"bun"` key). This is the standard Bun convention.

No other changes to package.json — scripts, deps, `type: "module"` all
stay the same. `@types/node` stays as a devDep since Vite's types
reference it.

### 3. Update `Makefile`

Replace all `pnpm` invocations with `bun`:

```makefile
# Before
build-frontend:
	cd frontend && pnpm install && pnpm build

dev:
	@echo "Run in separate terminals:"
	@echo "  cd crates/server && cargo run"
	@echo "  cd frontend && pnpm dev"

check:
	cargo check
	cd frontend && pnpm check
```

```makefile
# After
build-frontend:
	cd frontend && bun install && bun run build

dev:
	@echo "Run in separate terminals:"
	@echo "  cd crates/server && cargo run"
	@echo "  cd frontend && bun dev"

check:
	cargo check
	cd frontend && bun run check
```

`bun dev` works without `run` because Bun passes unknown subcommands to
package scripts. `bun run build` and `bun run check` are explicit to avoid
ambiguity with Bun's built-in `bun build` command.

### 4. Update `frontend/.gitignore`

Replace pnpm-specific log patterns with bun equivalents:

```gitignore
# Before
pnpm-debug.log*

# After (no bun-specific log files needed, but clean up the stale ref)
```

Just remove the `pnpm-debug.log*` line. Bun doesn't produce debug log
files in the same way.

### 5. Update root `.gitignore`

No changes needed. `/frontend/node_modules/` and `/frontend/dist/` are
already ignored. Bun uses `node_modules/` too, and `bun.lock` should be
committed (same as `pnpm-lock.yaml` was).

### 6. Update `AGENTS.md`

Two lines reference pnpm:

```markdown
# Before
cd frontend && pnpm test   # vitest
Package managers: Cargo (backend), pnpm (frontend).
```

```markdown
# After
cd frontend && bun test    # vitest
Package managers: Cargo (backend), bun (frontend).
```

### 7. Run `bun install` and verify

From `frontend/`:

```sh
bun install
```

This generates `bun.lock` (text format) and populates `node_modules/`
with Bun's flat layout.

### 8. Verify build and tests

```sh
cd frontend && bun run build   # should produce dist/ identically
cd frontend && bun test        # vitest should pass
cd frontend && bun run check   # svelte-check + tsc should pass
```

### 9. `vite.config.ts` — no changes needed

`import path from 'node:path'` works identically under Bun's runtime.
Vite runs via `bun run dev` / `bun run build` which uses Bun as the
runtime, and Bun has full `node:path` compatibility.

## Files Changed

| File                      | Action | What changes                                         |
| ------------------------- | ------ | ---------------------------------------------------- |

| `frontend/bun.lock`       | Create | Generated by `bun install`                           |
| `frontend/package.json`   | Edit   | `pnpm.onlyBuiltDependencies` → `trustedDependencies` |
| `Makefile`                | Edit   | `pnpm` → `bun` in all commands                       |
| `frontend/.gitignore`     | Edit   | Remove `pnpm-debug.log*`                             |
| `AGENTS.md`               | Edit   | `pnpm` → `bun` references                            |

## What doesn't change

- `vite.config.ts` — works as-is under Bun
- `tsconfig*.json` — runtime-agnostic
- `svelte.config.js` — runtime-agnostic
- `components.json` — runtime-agnostic (shadcn CLI: `bunx` instead of
  `npx`, but that's a user command, not config)
- All source code — zero Node.js API usage in app code
- `index.html`, `main.ts`, `app.css` — browser code, unaffected
- Backend Rust code — no awareness of frontend package manager

## Testing

- `bun install` completes without errors
- `bun run build` produces `frontend/dist/` with same structure
- `bun test` passes all vitest tests
- `bun run check` passes svelte-check and tsc
- `make build` succeeds end-to-end
- `make check` succeeds
- Dev workflow: `bun dev` starts Vite dev server, HMR works, proxy to
  :3001 works
